## 用户明确的工作约定

- 任务书优先于冲突样例/接口数值。不会使用 request.txt 的一级射程4/7/全图。
- 回合从1开始：白天1—70，夜晚71—130。
- 死亡后下一天白天开始20回合后复活。此版具体采用次日第21个白天回合，例如第一天死亡，在151轮开始恢复；这是“经过20回合”的索引解释，待真实日志校准。
- 同轮卖矿、任务等奖励所得金币不能用于同轮买/建；审计基于开轮余额。

## 已有能力与实现缺口

### 参赛程序

- 实现标准HTTP入口、完整12动作结构审计、开轮共享资源预留、幂等重复请求缓存、双队记忆隔离。
- 自动执行移动、建造、采矿、售卖、购买升级券、升级、回血、任务领取/提交、三种武器攻击及确定条件下宝藏流程。
- 配炮默认火箭/电磁/加特林各一座；优先取最短到位路径；随天数增加墙体投资，保留两处出口；这不是最优配比结论。
- 动作失败后重新使用真实观测规划；采矿失败点暂避4轮；火箭冷却缺失时用自身发射历史保守推断。
- 新闻每天一次LLM请求，提取闭矿约束与宝藏条件；任务期间按跨轮返回结果继续探索、提交；绝不在参赛进程本机执行 executeCmd。
- 内置sum/min/max/sort公开结构化题适配。其他任务依赖判题器提供真实LLM及沙盒；本地默认替身不生成答案。
- 未做完整自适应召唤令/炸弹/眩晕采购与战斗使用策略、自动拆墙/丢弃/维修优化；协议与本地执行支持这些动作，但策略不主动覆盖全部动作。
- 新闻自然语言可靠性、任务泛化效果、主动攻击对方建筑/角色仍未验证；本版伤害模型只对机器人结算。
- 任务SOP按会话存于内存；没有跨进程或跨半场持久化，避免串局。
- 2.5秒软计算预算约束重选靶；不是进程级硬实时保证。正式HTTP5秒仍需官方机器实测。

### 本地判题器

- 双队公开观测、两格任务点、统一碰撞、攻击/道具、资源消耗、复活、任务、宝藏、生存、异常停调、同图换边对照。
- 支持self、Demo、idle对手，支持真实HTTP调用和JSONL逐轮观测/响应记录。
- 完整1300轮与双方基地毁、双方异常5次终止；部分轮次调试报告complete=false，不擅自宣判完整胜负。
- 可注入ReplayServices测试LLM与沙盒返回；本地不提供真正隔离沙盒、不执行shell、不会联网调用付费模型。默认命令返回JUDGER_ERROR，LLM为空。
- HTTP模式连接超时10秒、读响应超时5秒；进程内模式只测总耗时，超过5秒记异常，无法强制中断死循环。测试不可信程序应使用外部HTTP进程。
- 真实网络故障、官方CPU/内存限制、官方LLM延迟和运行沙盒15秒超时未做完整环境复刻，只验证回传格式与状态。
- 同时结算采用明确规则；未完整定义的次序均列入A05。不以本地成绩倒改规则常量。

## 验证边界

单元测试采用独立手算值，包括电磁10能量依次打6血/20血得6/4、双火箭中心40邻格20、全程生存550。
即使策略和模拟器共用基础规则工具，回归预期也不是由同一函数生成。
本地对抗报告保存代码SHA256、官方文档/图片SHA256、种子、阵营、压力、Python版本、异常/执行失败和延迟。
修改后的旧报告只代表其hash对应旧代码。演示数值任务很容易完成，1200任务分等结果不可外推官方任务成绩。

真实判题日志到来后：保留原始日志 → 脱敏与提取单轮请求/响应 → 独立失败预期 → 修正规则实现或隔离假设 → 单测/换边留出回归 → 新报告。
