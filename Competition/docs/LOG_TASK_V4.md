## 本程序问题：证实与推断分开

**代码可确认的缺陷**：v3一发出献祭就永久屏蔽方案，未区分非法动作、时间未到、物品错和成功；
新传闻/否定推断也可能没有清除旧的certain计划；每天一次新闻推理失败后不重试。
日志重复完整请求、session、哈希、历史信息，且答案与下一轮反馈缺少直观关联。

**有依据的效率瓶颈**：指向任务文件的题目仍先调用LLM，通常需要“LLM要求读文件→沙盒读文件→LLM求解”，
浪费一轮；题目超时按附近点最小值猜测，可能不是实际领取点；没有checker成功TOKEN输出适配，
部署题不能利用明确的成功结果直接提交。

**还不能确认**：我方正式对局是否遇到错路径、HTTP鉴权、分页漏读、字段格式、权限修复遗漏、LLM空响应或超时。
本摘录没有我方对应的phaseTask/llmResp/lastCmdResult/errors，不能把这些可能性当成已证实根因。
宝藏失败也不能仅凭前三天线索判断成某件物品错误。

## 自进化任务的新流程

1. 保存实际接取点和超时数。若题面指向md/txt/rst文件，立即通过executeCmd进行只读探测。
2. 探测范围为当前沙盒目录、当前对局之前观察到的任务目录和/tmp，限制深度6、目录6000、约3秒。
   不全盘扫描，不执行文件内容，不从检查器源码取答案；多个同名文件时报告歧义。
3. 返回本题原文（最多20000字节）及同目录API_DOCS/spec/README（各6000字节），显式标记截断。
   截断或有歧义时仍需模型按已知路径进一步读取，不能假装文档已完整。
4. 模型看到实际原文后，在官方沙盒调用本机API，或读取/修复本题工作区并复检；每条命令显式切换本题目录。
   提示核查分页、筛选、字段含义、排序及提交格式，不把上一题城市、目录、token复制到新题。
5. checkerToken快路要求模型明确选择该格式，依据的是实际检查输出，不是最终判题器认证；提交后的真实反馈仍必须处理。
6. 保留v3的错答修正、任务期间不外出购物、成功SOP复用、失败输出不直接提交。

这里只实现通用读取/校验/模型协作流程，没有硬编码文化遗产统计或alpha/beta修复脚本。
真实题目语义求解仍依赖比赛提供的LLM与沙盒，本地题库成功不能宣称正式六题全对。
